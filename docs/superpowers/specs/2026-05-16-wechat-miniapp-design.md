# 微信小程序改造设计

## 本次定位

本次不是把现有 `frontend/` 商家后台直接硬迁移到小程序，而是单独新增一个 `miniapp/` 原生微信小程序工程，优先覆盖最适合微信场景的顾客链路：

- 顾客扫码进入桌台
- 可选手机号登录
- 浏览菜单并下单
- 查看当前桌台订单状态
- 查看会员积分与消费记录

商家后台继续保留 Web 端，避免把复杂表格和后台操作强行塞进小程序。

## 技术选择

选择原生微信小程序而不是再套一层 WebView 或引入新的跨端框架，原因：

- 直接在微信开发者工具可运行
- 不引入额外构建依赖，接入成本低
- 更贴近扫码点餐的真实交互场景
- 现有后端接口已经足够支撑顾客端 MVP

## 页面结构

### 1. 入口页 `pages/entry`

- 读取 `tableId` 或 `scene`
- 展示桌台信息
- 支持手机号可选登录
- 完成桌台上下文初始化

### 2. 菜单页 `pages/menu`

- 展示分类与搜索
- 菜品卡片化
- 固定底部购物袋
- 支持备注
- 提交订单后进入进度页

### 3. 进度页 `pages/status`

- 展示当前桌台所有有效订单
- 展示订单状态与菜品状态
- 10 秒自动刷新

### 4. 我的页 `pages/mine`

- 展示手机号会员信息
- 展示消费记录
- 展示积分明细

## 视觉方向

小程序不沿用 Element Plus 后台风格，而是改成更适合餐饮场景的铜暖色视觉：

- 主色：铜红、炭黑、米纸色
- 结构：上部气氛英雄区 + 下部纸感内容卡片
- 交互：大圆角、强层次、底部悬浮操作区

## 后端复用策略

沿用现有接口：

- `/api/c/auth/login`
- `/api/c/dish/list`
- `/api/c/order/create`
- `/api/c/order/table/{tableId}`
- `/api/c/customer/info`
- `/api/c/customer/orders`
- `/api/c/customer/points`

新增接口：

- `/api/c/table/{id}`：供小程序入口读取桌台名称与区域

## 下一阶段建议

如果继续推进，可以按下面顺序扩展：

1. 商家端生成小程序码，而不是现在的 H5 链接二维码
2. 接入微信手机号授权登录
3. 小程序订单状态页增加退款 / 退菜反馈提示
4. 商家侧新增“小程序装修配置”，支持主题和桌贴文案
